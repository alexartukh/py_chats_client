# Django React Client

Клиент (SPA) форума с комментариями — фронтенд к серверу на Django.
Пользователи регистрируются, создают темы и пишут в них сообщения деревом ответов
с разрешённой HTML-разметкой, вложениями (картинка или текстовый файл) и CAPTCHA.

Сервер — отдельный проект (Django, Django ORM, PostgreSQL, JWT, WebSocket). Клиент общается с ним только через HTTP API и WebSocket.

## Технологии

| Что | Версия | Зачем |
|---|---|---|
| React | 18.3 | интерфейс |
| React Router (`react-router-dom`) | 6.28 | страницы и переходы без перезагрузки |
| Vite | 6 | сервер разработки, сборка, proxy к Django |
| `@vitejs/plugin-react` | 4.3 | поддержка JSX в Vite |
| Fetch API | — | HTTP-запросы к серверу (JSON) |
| WebSocket API | — | список пользователей онлайн в реальном времени |
| JWT | — | вход: токен от сервера хранится в `localStorage` и уходит в заголовке `Authorization: Bearer <token>` |
| CSS | — | один файл `src/index.css`, без UI-библиотек |

Других зависимостей нет: ни UI-библиотек, ни менеджеров состояния, ни HTTP-клиентов.

## Возможности

### Пользователи и вход
- Регистрация: логин, email, пароль и его подтверждение. После регистрации пользователь сразу входит.
- Проверка на клиенте по тем же правилам, что на сервере: логин — только латинские буквы и цифры, email — формат `name@example.com`, оба не длиннее 255 символов.
- Вход и выход формой в шапке. После выхода открывается главная страница.
- В шапке — логин и email вошедшего и список других пользователей онлайн (WebSocket, сервер сам присылает изменения; при обрыве соединение восстанавливается через 3 с).
- Сессия истекла (сервер ответил 401 на защищённый запрос) — клиент сам выходит и открывает главную.
- Защищённая страница создания темы: без входа — перенаправление на главную.

### Главная страница
- Таблица пользователей: логин, email, дата регистрации.
- Таблица тем: id, название, автор, дата. Клик по строке открывает тему.
- Ссылки «Создать юзера» (только без входа) и «Создать тему» (только после входа).

### Страница темы
- Заголовок: название темы, автор, дата.
- **Таблица корневых сообщений** (не ответов) с сортировкой на клиенте по автору, email и дате, по возрастанию и убыванию. По умолчанию — новые сверху (LIFO).
- **Все сообщения деревом**: ответ стоит под своим родителем с отступом по глубине вложенности.
- **Пагинация по 25 сообщений**, порядок LIFO. У каждого сообщения — его номер на странице и в теме.
- Текст с разрешёнными тегами показывается отформатированным, с ошибкой в разметке — обычным текстом.
- Вложения: картинка — превью 160×120, по клику открывается в окне просмотра (Lightbox) до 320×240 с анимацией появления; `.txt` — текстом.
- Кнопки «Комментировать» (ответ на сообщение) и «Добавить корневой» — только после входа.
- «Удалить» — только автору сообщения, с подтверждением: вместе с сообщением удаляются все ответы на него.

### Форма сообщения (модальное окно)
- Поля: логин и email (из сессии, только для чтения), Home page (необязательное, формат url), CAPTCHA, текст, файл. Обязательные поля помечены красной `*`.
- **Панель кнопок `[i]` `[strong]` `[code]` `[a]`**: вставляет теги в позицию курсора или оборачивает выделенный текст.
- **Предпросмотр без перезагрузки** рядом с полем текста; при ошибке в разметке — красное сообщение.
- **CAPTCHA**: картинка с сервера, кнопка «↻» для новой. После любой неудачной отправки новая капча запрашивается сама (сервер сжигает капчу при каждой попытке).
- **Проверки до отправки**: разметка текста; файл — только JPG, GIF, PNG или TXT, `.txt` не больше 100 КБ, имя не длиннее 255 символов.
- Файл передаётся в JSON строкой base64. Картинку больше 320×240 сервер уменьшает перед сохранением.

### Разметка сообщений
Разрешены только теги из ТЗ: `<a href="" title="">`, `<code>`, `<i>`, `<strong>`.
- Все теги должны быть закрыты и правильно вложены (валидный XHTML); `<a>` внутри `<a>` запрещён.
- `href` — пустой или начинается с `http://` / `https://` (`javascript:` и прочее запрещено).
- Любой другой тег, атрибут или одиночный `<` — ошибка.

Проверка — функция `isMessageCorrect` в `src/messageMarkup.js`, её копия работает на сервере.

### Безопасность
- **XSS.** Всё, что выводится обычным способом, React экранирует сам. HTML вставляется (`dangerouslySetInnerHTML`) только в двух местах — предпросмотр и текст сообщения — и только после проверки `isMessageCorrect` по белому списку тегов.
- **Вложения:** картинка показывается как `data:image/...` с типом из таблицы по расширению; `.txt` — как текст.
- **SQL-инъекции** — на стороне сервера (Django ORM, без сырого SQL).

### Ошибки
- Если сервер прислал `{"error": "..."}` — показывается его текст.
- Иначе — понятный текст по коду ответа (400, 401, 403, 404, 409, 413, 5xx).
- Сервер недоступен — «Сервер недоступен. Проверьте, что он запущен, и повторите».
- Даты показываются как `17.10.2026 23:16:14` в часовом поясе браузера.

## Запуск

Нужны Node.js и запущенный сервер Django на `http://localhost:8000`.

```
npm install
npm run dev
```

Открыть http://localhost:5173.

Vite пересылает запросы `/api/...` и WebSocket `/ws/...` на `localhost:8000` (`vite.config.js`), поэтому браузер видит один адрес и CORS при разработке не нужен.

## Сборка для хостинга

Если клиент и сервер на разных адресах, адрес сервера задаётся переменной `VITE_API_BASE` при сборке:

```
VITE_API_BASE=https://адрес-сервера npm run build
```

Готовые файлы — в `dist/`. Без `VITE_API_BASE` запросы идут на тот же адрес, с которого открыта страница. WebSocket идёт на тот же сервер: `https://` → `wss://`.

## Структура

```
src/
  main.jsx               точка входа: BrowserRouter + AuthProvider
  App.jsx                маршруты
  api.js                 все запросы к серверу (адреса, обработка ошибок, выход при 401)
  useOnlineUsers.js      WebSocket со списком онлайн
  messageMarkup.js       проверка разрешённой разметки (isMessageCorrect)
  inputValidation.js     проверки логина, email и файла — те же правила, что на сервере
  dateFormat.js          формат даты "ДД.ММ.ГГГГ чч:мм:сс"
  index.css              все стили
  context/AuthContext.jsx  состояние входа: токен, логин, email; login, logout, createNewUser
  layouts/MainLayout.jsx   шапка + страница + подвал
  pages/                 HomePage, TopicPage, CreateNewUserPage, CreateTopicPage
  components/            MainHeader, MainFooter, UsersList, TopicsList, RootMessages,
                         EnterMessage (форма сообщения), MessageAttachment, Lightbox, ProtectedRoute
```

## Маршруты

| Адрес | Страница | Доступ |
|---|---|---|
| `/` | главная: пользователи и темы | всем |
| `/create_new_user` | регистрация | всем |
| `/topic/:topicId` | тема: сообщения | читать — всем, писать и удалять — после входа |
| `/create_new_topic` | новая тема | только после входа |

## Используемые запросы к серверу

| Запрос | Для чего |
|---|---|
| `POST /api/login`, `POST /api/logout` | вход и выход |
| `POST /api/create_new_user` | регистрация (сразу возвращает токен) |
| `GET /api/users` | список пользователей |
| `GET /api/topics`, `GET /api/topic?topic_id=` | темы и одна тема |
| `POST /api/create_new_topic` | новая тема |
| `GET /api/messages?topic_id=&from=&to=` | сообщения темы деревом, страница `from..to` |
| `GET /api/get_all_root_messages?topic_id=` | корневые сообщения для таблицы |
| `POST /api/create_new_message` | новое сообщение или ответ |
| `POST /api/delete_existing_message` | удаление своего сообщения |
| `GET /api/captcha` | новая CAPTCHA: `captcha_id` и картинка |
| WebSocket `/ws/online?token=` | список пользователей онлайн |

Защищённые запросы отправляются с заголовком `Authorization: Bearer <token>`.

## Ограничения

- Правила проверки (разметка, логин, email, файл) записаны и на клиенте, и на сервере. При изменении их нужно менять в обоих местах.
- Новые сообщения других пользователей появляются только после перезагрузки страницы: WebSocket используется только для списка онлайн.
- Таблица корневых сообщений не разбита на страницы, по 25 разбито только дерево сообщений.
- Токен хранится в `localStorage`.
